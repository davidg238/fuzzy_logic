# Deploying to an ESP32

The Toit engine is designed to run on ESP32 hardware. Three storage patterns are supported, in increasing order of "model lives outside the binary." Pick the one that matches how you'll update the model after deployment.

## Prerequisites

- An ESP32 already flashed with [Jaguar firmware](https://github.com/toitlang/jaguar) and reachable on your LAN (`jag scan` lists it).
- `fuzzy_logic` added to your project's `package.yaml`:

  ```yaml
  dependencies:
    fuzzy-logic:
      url: github.com/<owner>/fuzzy_logic
      version: ^0.8.0
  ```

Then `jag toit pkg install` in your project directory.

## Pattern 1 — Inline `Map` literal *(smallest binary, fixed model)*

The model is a Toit `Map` constant compiled into the binary. No `encoding.json`, no `host.file`, no network code.

```toit
import fuzzy-logic show *
import fuzzy-logic.json-loader show load-model

MODEL ::= {
  "name": "thermostat",
  "inputs":  [...],
  "outputs": [...],
  "rules":   [...],
}

main:
  model := load-model MODEL
  while true:
    model.crisp-input 0 (read-temperature-sensor)
    model.fuzzify
    set-fan-speed (model.defuzzify 0)
    sleep --ms=1000
```

**Use when:** model is fixed for the device's lifetime, or model + firmware are versioned together.
**Footprint:** engine + json-loader only. No `pkg-http`, no `pkg-host`, no `pkg-net`.
**See:** `examples/simple.toit`.

## Pattern 2 — JSON string constant *(smallest binary, model authored elsewhere)*

The model is a multi-line JSON string parsed with `encoding.json` at boot. Behaviorally identical to Pattern 1, but lets you keep the authoritative model as `.json` source and paste it in. Useful when the model is generated by `fcl2json` and you don't want a runtime file-system dependency.

```toit
import encoding.json
import fuzzy-logic show *
import fuzzy-logic.json-loader show load-model

MODEL ::= """
{
  "name": "thermostat",
  "inputs":  [...],
  "outputs": [...],
  "rules":   [...]
}
"""

main:
  model := load-model (json.parse MODEL)
  ...
```

**Use when:** authoring in `.fcl` or `.json` is preferred for legibility, but the model still ships in firmware.
**Footprint:** engine + json-loader + `encoding.json` (built-in to the SDK).
**See:** `examples/embedded.toit`.

## Pattern 3 — Load JSON from flash *(model updatable without reflashing)*

The model lives as a `.json` file in the device's flash filesystem, read at boot. Requires `pkg-host` (for `host.file`) — fine on host runs and on ESP32 (where `host.file` reads from the device's asset/flash partition).

```toit
import encoding.json
import host.file as file
import fuzzy-logic show *
import fuzzy-logic.json-loader show load-model

MODEL-PATH ::= "fcl/generated/tipper.json"

main:
  text := (file.read-contents MODEL-PATH).to-string
  model := load-model (json.parse text)
  ...
```

**Use when:** you want to update the model independently of the firmware (e.g., push a new `.json` via `jag pkg`, OTA, or your own mechanism).
**Footprint:** engine + json-loader + `encoding.json` + `pkg-host`.
**See:** `examples/device.toit`.

## Optional: add the HTTP service

Any of the three patterns can additionally start `RpcService` so the device responds to remote commands (set inputs, replace model, read state). This brings in `pkg-http`:

```toit
import net
import fuzzy-logic.rpc-service show RpcService

main:
  ...
  network := net.open
  service := RpcService model network --port=8090
  print "fuzzy_logic RpcService on :8090"
  service.start
```

Pair with `fuzzy-lab` running on a laptop (`uv run fuzzy-lab --connect http://<device-ip>:8090`) to drive the device live and see what it's doing. Endpoint reference: [rpc-service.md](rpc-service.md).

## Running and installing on the device

`jag run` runs a program once and stops; `jag container install` keeps it running across reboots.

```bash
# Find your device:
jag scan

# Run once (good for debugging):
jag run --device <name> main.toit

# Install as a persistent container:
jag container install --device <name> thermostat main.toit

# Watch serial output:
jag monitor -a
```

The container survives power cycles. Remove with `jag container uninstall thermostat --device <name>`.

## Sizing footprint by pattern

| Pattern | Engine | json-loader | encoding.json | pkg-host | pkg-http |
|---|---|---|---|---|---|
| 1 (inline Map) | ✓ | ✓ | — | — | — |
| 2 (JSON string) | ✓ | ✓ | ✓ | — | — |
| 3 (JSON file) | ✓ | ✓ | ✓ | ✓ | — |
| any + RpcService | ✓ | ✓ | ✓ | (Pattern 3 only) | ✓ |

`encoding.json` is in the Toit SDK — no `package.yaml` entry needed. `pkg-host` and `pkg-http` are declared in your project's `package.yaml` only when you import them.

## Troubleshooting

- **"didn't find any Jaguar devices"** — the device may be booting; retry after 10s. `jag scan` confirms it's online.
- **`FILE_NOT_FOUND` on Pattern 3** — the JSON file isn't on flash. The path is relative to the device's filesystem root; bundle the file as an asset (`jag pkg`) or use Pattern 2.
- **`Package for prefix 'host' not found`** — `pkg-host` isn't in your `package.yaml`. Add it under `dependencies:` and run `jag toit pkg install`.
- **Crisp output is NaN** — usually means no rule fired (all antecedent powers are 0). Inspect `model.serialize-state` to see per-term pertinences.
